# 吃点什么 · 自用 PWA v0.4

手机优先、纯 HTML/CSS/JavaScript，部署到 GitHub Pages。健康档案与使用记录保存在当前浏览器，不上传。不提供具体医疗建议。

## 信息库与个人记录

- **应用食谱库**：`data.js` 的 42 份离线食谱，加上后台自动获取的 HowToCook 中文食谱。它是推荐数据，不是用户的常吃清单。用户不需要添加、编辑、导入或确认食谱资料。
- **常吃清单**：初始为空。点击“就吃这一套”或“再吃这套”后，自动记录一次采纳；按餐食合并，显示采纳次数、实际吃过次数、最近采纳日期。浏览、换一套不会加入。
- **餐食计划**：本次已选的餐食。采纳不等于已经吃过；更换计划仍保留曾经采纳的记录。
- **吃过历史**：点击“我吃过了”记录实际用餐，可反馈和备注，不重复累计采纳次数。

旧版本升级从吃过历史和现有计划恢复有证据的采纳记录。预塞模板不会被当成用户采纳。已有档案、用餐记录和用户编辑过的旧数据保留；旧自定义数据不自动成为常吃记录。

## 推荐体验

首次直接进入四步建档：忌口与过敏、健康背景、口味二选一、近期目标与保存。可编辑减脂／健身／两者兼有等目标。目标只影响口味和配料特征排序，不计算能量目标或制定健康方案。

首页一次只推荐一套餐食，显示推荐理由，点“换一套”直接更换。独立菜品可补充主食、蔬菜或豆腐搭配，整套重新匹配食物限制。已选计划不会同时展示第二套推荐。“本次考虑了什么”在推荐之后折叠展示。没有预算、时间估计或筛选。

## 食谱匹配范围

程序按食谱的中文配料、常见别名及酱油等调料信息，匹配明确忌口、过敏食材、口味和目标。不把“人工确认完整配料”作为使用入口，不要求用户核实食谱。无法识别的过敏原或资料不足以执行当前限制的食谱，自动跳过。

**交叉接触、共用厨具信息不作为筛选项，也没有对应确认控件。** 应用无法求证制作环境。旧备份中的 `complete`、`crossContact` 字段仅为兼容保留，不参与推荐决策。

筛选是食谱信息层面的匹配，不代表实际餐品、商家或制作环境的安全验证。桥本、银屑病及异常体检项可记录，但没有经专业审核的疾病个体适宜性规则；不会因此生成统一禁食表或提供治疗建议。

## 中文来源与自动更新

使用 [HowToCook](https://github.com/Anduin2017/HowToCook)，遵循其 [Unlicense](https://github.com/Anduin2017/HowToCook/blob/master/LICENSE)。联网食谱有原文中文做法链接。它是烹饪资料，不是医疗数据库。

建档完成或老用户打开时自动获取公开目录，从荤菜、素菜、水产、主食、早餐、汤等分类每天轮换读取最多 24 份，并按目录的同一提交版本读取文件。并发最多 4 个，总超时 18 秒，成功结果缓存 24 小时。没有独立搜索页。断网或来源不可用时使用缓存与内置食谱。

请求不发送档案、偏好答案、历史、目标、定位或想吃内容；筛选在本机完成。GitHub 服务可接收常规访问元数据。远端 Markdown 不作为 HTML 执行。

## 运行和部署

需要 Node.js 22 运行测试，无需安装依赖：

```sh
npm test
python3 -m http.server 4173 --bind 127.0.0.1
```

浏览器打开 `http://localhost:4173/`。不要直接双击 HTML，模块与 Service Worker 需要 HTTP(S)。手机安装与离线使用通过部署后的 HTTPS 地址验证。

在 GitHub 仓库 Settings → Pages 将 Source 设为 GitHub Actions，提交并推送到 `main` 即触发 `.github/workflows/pages.yml`。工作流只发布静态程序白名单，支持项目子路径。

本次修改在本地，尚未推送。部署后接受一次应用更新即可，无需删除个人档案。后续发布同时修改 `updates.js` 的 `APP_VERSION`、`sw.js` 的缓存版本和 `GET_VERSION` 返回值。

## 数据与备份

“我的 → 备份与恢复”导出或恢复完整私人备份，包含健康档案、采纳记录和吃过历史。备份不要放入公开仓库。恢复会替换本机记录，并要求按最新档案重新检查已有计划；重新检查不会新增采纳次数。

localStorage 没有额外加密；同设备不同浏览器不自动同步，清理网站数据可能丢失记录。同一网站来源下其他脚本具有同源访问能力。没有账号或分析追踪。

## 实现与验证

- `data.js` / `online.js`：应用食谱库、中文来源与解析。
- `recommendations.js`：来源缓存、整餐组合、统一推荐。
- `core.js`：档案验证、食材匹配、采纳记录、计划、历史、迁移与备份。
- `app.js`：建档、单套推荐、常吃清单、历史界面。
- `sw.js` / `updates.js`：离线壳与版本更新。

45 项自动测试覆盖数据分离、常吃清单从空开始、采纳与吃过次数、重复选择、旧记录迁移、交叉接触字段不影响筛选、食材限制、自动获取、单套展示及更新版本判断。

真实浏览器联网、手机布局与安装流程尚未在本环境验证；此前启动本机预览服务器时自动审批服务返回 503，命令未执行。
